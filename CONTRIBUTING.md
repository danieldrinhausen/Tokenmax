# Contributing

Thanks for looking. Tokenmax is a small personal tool, so the bar here is
"does this stay understandable a year from now", not process for its own sake.

## Getting set up

```
brew install xcodegen
make test       # full suite, no network, no side effects
make doctor     # check the upstream surfaces this app does not own
make install    # build, sign, install to /Applications
```

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) is worth reading before a first
change — particularly [the drift map](docs/ARCHITECTURE.md#the-drift-map), which
covers what breaks when Claude Code changes and how each failure announces
itself.

Requires Xcode 26+. `Tokenmax.xcodeproj` is generated by `xcodegen` from
`project.yml` and is deliberately not tracked — edit `project.yml`, never the
project file.

Tests run with `TOKENMAX_SUPPORT_DIR=/tmp/tokenmax-tests`, so they never touch
your real queue or settings in `~/Library/Application Support/Tokenmax/`.

## What a good change looks like

**Keep the decisions pure.** The pattern the codebase leans on is a plain
`enum`/`struct` that decides *what* to do from data passed in, and a separate
`@MainActor` coordinator that owns the clock, the processes and the files.
`SessionOpener` / `SessionOpenerCoordinator` and `NotificationScheduler` /
`NotificationCoordinator` are the models to copy. It exists so every rule is
unit-testable without a running app, and it is the main thing to preserve.

**Name every suppression.** When something decides *not* to act, that reason is
a case in an enum with human-readable copy, not a bare `return`. The user can
see it in Settings and it shows up in the log. A new guard means a new case.

**Comment the why, not the what.** Most comments here explain a constraint that
is not visible from the code — a 180-second rate floor, a timestamp that jitters
by a second, an ordering that exists because of a bug. Match that.

**Anything that spends quota is guarded.** The session opener and the queue
runner both spend real money on someone's plan. New code on those paths needs a
test that proves it refuses in the unsafe case, and ambiguity resolves to "do
not spend".

**Add tests.** Swift Testing (`@Test`, `#expect`). Give the test a sentence-long
name that states the rule, so a failure explains itself.

## Pull requests

CI runs `make test` on macOS; it must be green. Keep the diff focused — one
change per PR — and say in the description what user-visible behaviour changes.

If you are planning something large, open an issue first so we can agree on the
shape before you spend the time.

## Reporting bugs

Include your macOS version, whether the app was built locally or installed from
a release, and the relevant lines from `make logs`
(`~/Library/Application Support/Tokenmax/logs/tokenmax.log`).

The log records decisions like `opener: extraUsageEnabled` and
`autorun: noSessionWindow` — those lines are usually the whole answer, so please
include them. **Scrub anything private first**: the log records queue task text
and working directory paths.
