# AGENTS.md

Operating notes for AI coding agents working in this repository. Human-facing
docs live elsewhere and are linked where they go deeper — this file is the
short version of what you need to not break things.

## What this is

A macOS menu bar app (SwiftUI, no third-party dependencies) that reads Claude
Code and Codex quota, projects burn rate, and runs a local prompt queue —
including unattended runs that **spend real money on the user's plan**. Treat
anything on that path as safety-critical.

## Commands

```
make build     # compile
make test      # full suite — must be green before you claim done
make doctor    # check upstream surfaces (CLI flags, endpoints, keychain shape)
make install   # build, sign, install to /Applications  (stops the running app)
make run       # launch the installed copy
make logs      # tail the log
```

- **Never edit `Tokenmax.xcodeproj`.** It is generated by `xcodegen` from
  `project.yml` and is not tracked. Edit `project.yml`.
- Tests run with `TOKENMAX_SUPPORT_DIR=/tmp/tokenmax-tests` and never touch real
  user state. They make no network calls.
- `xcodebuild` output is noisy; a build can succeed while printing CoreSimulator
  version warnings and an `error:` line about simulator devices. **Check the exit
  code**, not a grep for "error".
- Getting the test count: read `passedTests` from the `.xcresult` bundle via
  `xcrun xcresulttool`. `make test` is `-quiet` and prints no summary.

Requires macOS 14+ at runtime, Xcode 26+ to build. `SWIFT_STRICT_CONCURRENCY` is
`complete` — new types crossing actor boundaries must be `Sendable`.

## The one architectural pattern

Every feature splits into a **pure decision type** and a **side-effecting
coordinator**:

| Decision (enum/struct) | Coordinator (`@MainActor`) |
|---|---|
| `SessionOpenerDecision` | `SessionOpenerCoordinator` |
| `NotificationScheduler` | `NotificationCoordinator` |
| `QueueAutoRunDecision` | `QueueAutoRunCoordinator` |

Decision types take everything as parameters and return a verdict. They never
read a file, spawn a process, or call `Date()`. Coordinators own the clock,
processes and files, and hold no rules of their own.

**Follow this for new features.** It is why every rule here is testable without
a running app, and it is the property most worth preserving.

**Name every suppression.** When something decides *not* to act, that reason is a
case in an enum with human-readable copy — never a bare `return`. It surfaces in
Settings and in the log. A new guard means a new case.

## Invariants — do not "fix" these

- **`--dangerously-skip-permissions` is never passed.** Anywhere, under any
  setting.
- **File tools are path-scoped** to the task's working directory (`Write(**)`
  style). Without the scoping an allowlisted `Write` is auto-approved for *any*
  path on the machine.
- **Shell access is a separate per-task opt-in** because it escapes that
  confinement.
- **The session opener runs with all tools disabled and refuses to run under an
  API key.** These are invariants, not settings — a toggle for either would only
  be a way to disable the safety.
- **`ClaudeTaskRunner.environment` and `ClaudeOpenerRunner.environment`
  deliberately differ** — denylist for the runner (real projects need `PATH`),
  allowlist for the opener (which needs nothing). The comment there says not to
  make them consistent. Do not make them consistent.
- **The OAuth client's 180s request floor and `User-Agent: claude-code/<version>`
  header are non-negotiable** and enforced inside the client, not by callers.
  Without the header, requests land in an aggressively rate-limited bucket.
- **Never write credentials to disk, and never refresh the token** — refreshing
  would race Claude Code's own refresh.
- **Stale data postpones; it never cancels.** A failed refresh means "cannot
  currently confirm", not "the user does not want this". Reminders stay
  scheduled, the opener waits rather than skipping its cycle. Inverting this
  produces an app that silently dies after a network blip.
- **Decoders stay tolerant.** Every `decodeIfPresent(...) ?? default` is
  load-bearing: it lets old files open in new builds and vice versa. Unknown enum
  cases must fall back, not throw (see `QueueAutoRunState`, which decodes an
  unrecognised run status as `.interrupted`).

## Traps that have already bitten

- **A macOS menu-style `Picker` does not stretch to fill `.frame(width:)`.** It
  sizes to its widest menu item and SwiftUI then *centers* it, so the control
  drifts right of its label. Always pass `alignment: .leading` on pickers under a
  header label. `TextField` does stretch, which is why only pickers look wrong.
- **A `.segmented` Picker cannot hold a badge or per-segment styling.** It
  bridges to `NSSegmentedControl`, whose segments take a plain string title;
  nested views are flattened. Rich tabs must be hand-rolled buttons (see
  `QueueNavigationView`).
- **`QueueListModel.count(_:_:)` rebuilds the whole counts dictionary per call.**
  In a view that redraws every second, compute `counts(_:)` once and pass it down.
- **SourceKit reports phantom "Cannot find type X in scope" errors** for
  same-module types when the index is cold. Trust `make build`, not the
  diagnostics.

## Upstream coupling

This app has **no third-party dependencies**. Everything that can break is a
coupling to something outside the repo — CLI flags, an undocumented usage
endpoint, another app's keychain blob, two response schemas.

Each one is designed to *announce* itself rather than fail silently:

| Surface | How the failure surfaces |
|---|---|
| A renamed CLI flag | Run status `.incompatibleCLI` → "Update needed"; queue pauses |
| `stream-json` schema | Log: `transcript: … none recognised` |
| Usage response shape | `UsageClientError.schemaDrift`; log: `usage: SCHEMA DRIFT` |
| Endpoint moved, keychain reshaped, statusline payload changed | `make doctor` |

**If you change the flags passed to the CLI, update the flag lists in
`Tools/doctor.sh` to match.** They are intentionally duplicated so the check can
fail loudly.

Full detail: [docs/ARCHITECTURE.md → The drift map](docs/ARCHITECTURE.md#the-drift-map).

## Code style

- **Comment the why, not the what.** Almost every comment here explains a
  constraint invisible from the code — a rate floor, a timestamp that jitters, an
  ordering that exists because of a bug. Match that density and that register. Do
  not add comments restating the code.
- Match surrounding naming and idiom. This codebase has a distinctive, terse,
  declarative voice in both comments and user-facing copy; keep it.
- User-facing strings are complete sentences that say what happened and what to
  do about it.

## Testing

Swift Testing (`@Test`, `#expect`) — not XCTest. Give each test a sentence-long
name stating the rule, so a failure explains itself.

**Anything on a quota-spending path needs a test proving it refuses in the unsafe
case.** Ambiguity resolves to "do not spend".

Add negative tests, not just positive ones: a detector that fires correctly is
half-tested until you show it stays quiet on lookalike input.

`PersistenceCompatibilityTests` guards the tolerant-decoder property. Add a case
there when you add a persisted field.

## Before you claim done

1. `make build` exits 0.
2. `make test` — full suite green.
3. `make doctor` if you touched anything in `Providers/` or the CLI arguments.
4. Report honestly: if something is skipped or unverified, say so.

Do not run `make install` unless asked — it stops and replaces the user's running
copy.
